# Проектная работа: от макета Figma до готового HTML/CSS-проекта

> [!info] Цель
> В этой работе мы пройдём полный путь от готового макета в Figma до работающей веб-страницы:
>
> **Figma → анализ макета → подготовка проекта → HTML → CSS → проверка в браузере → готовый проект.**
>
> В качестве учебного проекта используется страница аукциона «Оно тебе надо».

---

## 1. Что мы делаем

Перед нами макет одностраничного сайта. В нём есть:

1. шапка сайта;
2. главное изображение с крупным заголовком;
3. кнопка;
4. секция с лотами;
5. три карточки;
6. секция «Об аукционе»;
7. подвал с контактами, меню и социальными иконками.

Наша задача — не просто повторить внешний вид, а научиться переводить визуальный макет в структуру HTML и правила CSS.

Главный принцип работы:

> **Не начинаем с CSS. Сначала изучаем макет и определяем структуру страницы.**

---

# 2. Как читать макет Figma

Figma показывает нам внешний результат, но браузер должен получить совершенно другую информацию.

В макете мы видим:

- прямоугольники;
- изображения;
- текст;
- линии;
- расстояния;
- группы элементов.

В HTML нам нужно определить:

- какие элементы являются заголовками;
- где находится навигация;
- где список;
- где карточка;
- где ссылка;
- где кнопка;
- где обычный текст.

А затем CSS отвечает за внешний вид.

Получается разделение ответственности:

| Задача | Инструмент |
|---|---|
| Содержание страницы | HTML |
| Структура страницы | HTML |
| Семантика | HTML |
| Цвета | CSS |
| Шрифты | CSS |
| Размеры | CSS |
| Отступы | CSS |
| Расположение | CSS |
| Фоновые изображения | CSS |
| Состояния кнопок | CSS |

# 3. Первый этап — изучаем макет

Прежде чем писать код, нужно определить основные размеры.

В нашем проекте основная ширина страницы — **1100 px**.

Это значение видно из макета и становится одним из первых параметров CSS:

```css
body {
  width: 1100px;
  margin: 0 auto;
}
```

## Что делает `width`

```css
width: 1100px;
```

задаёт ширину элемента.

В нашем случае ширина страницы составляет 1100 пикселей.

## Что делает `margin: 0 auto`

```css
margin: 0 auto;
```

означает:

- сверху и снизу — `0`;
- слева и справа — автоматический отступ.

В результате блок шириной 1100 px располагается по центру окна браузера.

# 5. Почему нельзя делать всю страницу одним `<div>`

Начинающий разработчик может написать:

```html
<div>
  ...
</div>
```

для каждого блока.

Браузер это позволит, но такая разметка плохо описывает смысл страницы.

HTML предоставляет семантические элементы.

Например:

```html
<header>
```

означает шапку;

```html
<nav>
```

означает навигацию;

```html
<main>
```

содержит основное содержимое;

```html
<section>
```

обозначает тематический раздел;

```html
<footer>
```

означает подвал.

Поэтому мы стараемся сначала определить **смысл элемента**, а уже потом его внешний вид.

# 7. Создаём базовый HTML-документ

Начинаем с:

```html
<!DOCTYPE html>
<html lang="ru">
```

## `<!DOCTYPE html>`

Сообщает браузеру, что документ использует современный HTML.

## `lang="ru"`

Сообщает браузеру, что основной язык страницы — русский.

Это важно:

- для доступности;
- для экранных дикторов;
- для поисковых систем;
- для корректного определения языка.

# 8. Создаём `<head>`

Используем:

```html
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <link rel="stylesheet" href="fonts/fonts.css" />
  <link rel="stylesheet" href="styles/global.css" />
  <link rel="stylesheet" href="styles/style.css" />
  <title>оно тебе надо</title>
</head>
```

## Кодировка

```html
<meta charset="UTF-8" />
```

Позволяет корректно отображать русский текст и другие символы.

## Viewport

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

Настраивает отображение страницы на устройствах с разной шириной экрана.

## Подключение CSS

```html
<link rel="stylesheet" href="styles/global.css" />
<link rel="stylesheet" href="styles/style.css" />
```

Браузеру сообщается, где находятся стили.

# 12. Навигация

Меню — это навигация, поэтому используем:

```html
<nav>
```

Сами пункты удобно представить списком:

```html
<ul>
  <li>
    <a href="#">главная</a>
  </li>
  <li>
    <a href="#">посмотреть лоты</a>
  </li>
  <li>
    <a href="#">об аукционе</a>
  </li>
</ul>
```

## Почему `<ul>`

Это действительно список ссылок.

HTML описывает структуру:

```text
список
 ├── пункт
 ├── пункт
 └── пункт
```

CSS позже превратит вертикальный список в горизонтальное меню.

# 13. Ссылка `<a>`

Например:

```html
<a class="header__link" href="#">главная</a>
```

`a` создаёт гиперссылку.

Атрибут:

```html
href="#"
```

пока является условным адресом.

В реальном проекте здесь появится настоящий URL или якорь.

---

# 14. Логотип

В центре располагается:

```html
<a class="header_logo" href="#">
  <img
    class="header_logo-image"
    src="images/logo-black.svg"
    alt="Логотип проекта"
  />
</a>
```

Здесь два разных элемента выполняют разные функции:

- `<a>` — делает логотип ссылкой;
- `<img>` — отображает изображение.

## `src`

```html
src="images/logo-black.svg"
```

указывает путь к изображению.

## `alt`

```html
alt="Логотип проекта"
```

текстовое описание изображения.

## `style.css`

# 17. Первое глобальное правило — `box-sizing`

Используем:

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

Звёздочка:

```css
*
```

означает «все элементы».

`::before` и `::after` — псевдоэлементы.

## Что делает `border-box`

При обычном расчёте ширины браузер может добавлять `padding` и `border` к указанной ширине.

С `border-box` указанная ширина включает:

- содержимое;
- padding;
- border.

Это делает расчёты размеров более предсказуемыми.

# 18. Сбрасываем стандартные отступы

Браузер самостоятельно добавляет отступы некоторым элементам.

Например, у заголовков и списков есть стандартные `margin` и `padding`.

В проекте используется:

```css
h1,
h2,
h3,
h4,
h5,
h6,
p,
ul,
ol,
li,
blockquote {
  margin: 0;
  padding: 0;
}
```

Теперь внешний вид контролируем мы сами.

# 19. Общие стили ссылок

```css
a {
  color: inherit;
}
```

`inherit` означает:

> взять значение у родительского элемента.

Это позволяет ссылкам наследовать цвет текста вместо стандартного синего.

# 20. Изображения

```css
img {
  width: 100%;
}
```

Изображение по умолчанию будет занимать ширину родительского элемента.

Это полезно для логотипов и других изображений, размер которых определяется контейнером.

---

# 21. Стилизуем Header

Основное правило:

```css
.header {
  display: grid;
  grid-template-columns: 1fr min-content 1fr;
  align-items: center;
  min-height: 293px;
}
```

Здесь находится важное решение.

---

# 22. Почему Grid

Нам нужны три области:

```text
1fr | min-content | 1fr
```

То есть:

```text
┌────────────┬──────────────┬────────────┐
│    меню    │   логотип    │  контакты  │
│    1fr     │ min-content  │    1fr     │
└────────────┴──────────────┴────────────┘
```

`min-content` позволяет центральной колонке занять необходимую ширину.

Две боковые колонки занимают оставшееся пространство.

Таким образом логотип оказывается по центру.

---

# 23. Горизонтальное меню через Flex

Для списка:

```css
.header_menu ul {
  display: flex;
  gap: 32px;
}
```

`display: flex` располагает элементы в одну линию.

`gap` создаёт расстояние между ними.

Получаем:

```text
главная    посмотреть лоты    об аукционе
```

без ручного добавления пробелов.

# 24. Маркеры списка

По умолчанию у `<ul>` есть маркеры.

В нашем дизайне часть маркеров нужна, поэтому используется:

```css
list-style: circle;
```

Но для первого пункта применяется отдельный класс:

```css
.header__links-list-item_no-bullit {

```

Это позволяет получить композицию, соответствующую макету.

# 25. Главная секция — Cover

В макете сразу после шапки находится большое изображение.

HTML:

```html
<section class="cover">
  <h1 class="cover_title">
    <span class="accent-span">оно</span>
    <span class="accent-span aligned-text_center">тебе</span>
    <span class="accent-span aligned-text_right">надо</span>
  </h1>

  <div class="overlay"></div>

  <div class="cover__description">

  </div>
</section>
```

# 26. Почему используется `<h1>`

Главный текст страницы:

```text
ОНО
ТЕБЕ
НАДО
```

является главным заголовком.

Поэтому используем:

```html
<h1>
```

а не обычный `<div>`.

---

# 27. Почему три `<span>`

Нам нужно получить:

```text
ОНО
        ТЕБЕ
              НАДО
```

Поэтому каждую строку делаем отдельным `span`:

```html
<span>оно</span>
<span>тебе</span>
<span>надо</span>
```

А затем:

```css
.accent-span {
  display: block;
}
```

Каждый `span` превращается в отдельный блочный элемент.

# 28. Выравнивание строк

Средняя строка:

```css
.aligned-text_center {
  text-align: center;
}
```

Последняя:

```css
.aligned-text_right {
  text-align: right;
}
```

Получаем визуальное расположение текста из макета.

# 29. Работа с типографикой

Для заголовка:

```css
.cover_title {
  color: #ffffff;
  font-family: "Raleway", sans-serif;
  font-weight: 700;
  font-size: 100px;
  line-height: 130px;
  text-transform: uppercase;
  letter-spacing: 0.3em;
}
```

Здесь каждое свойство отвечает за конкретную характеристику.

| Свойство | Назначение |
|---|---|
| `color` | цвет |
| `font-family` | шрифт |
| `font-weight` | насыщенность |
| `font-size` | размер |
| `line-height` | высота строки |
| `text-transform` | изменение регистра |
| `letter-spacing` | расстояние между буквами |

# 30. `padding` заголовка

```css
padding: 165px 50px 0;
```

Это сокращённая запись:

```text
верх:    165px
право:    50px
низ:       0
лево:     50px
```

То есть:

```css
padding-top: 165px;
padding-right: 50px;
padding-bottom: 0;
padding-left: 50px;
```

# 31. Фоновое изображение

У секции:

```css
.cover {
  background-image: url(../images/cover.jpg);
  background-repeat: no-repeat;
  background-size: cover;
  background-position: center;
}
```

## `background-image`

Задаёт изображение фона.

## `background-repeat`

```css
no-repeat
```

запрещает повторение изображения.

## `background-size: cover`

Изображение масштабируется так, чтобы полностью покрыть контейнер.

Часть изображения может выйти за границы контейнера — это нормально.

## `background-position: center`

Центр изображения совмещается с центром блока.

---

# 32. Почему фотография — background, а не `<img>`

В нашем случае фотография является **частью оформления блока**, а не самостоятельным содержательным изображением.

Кроме того, поверх неё размещаются:

- заголовок;
- текст;
- кнопка;
- затемнение.

Поэтому `background-image` здесь удобнее.

---

# 33. Затемнение фотографии

На изображении макета фотография затемнена.

Для этого создаём:

```html
<div class="overlay"></div>
```

и CSS:

```css
.overlay {
  position: absolute;
  inset: 0;
  z-index: -1;
  opacity: 0.6;
  background-color: #000000;
}
```

---

# 34. Зачем `position: relative`

У родителя:

```css
.cover {
  position: relative;
}
```

Это создаёт систему координат для абсолютно позиционированного `.overlay`.

Иными словами:

```text
cover
└── overlay
```

`overlay` позиционируется относительно `cover`.

---

# 35. Что означает `inset: 0`

Вместо четырёх свойств:

```css
top: 0;
right: 0;
bottom: 0;
left: 0;
```

можно написать:

```css
inset: 0;
```

Это означает:

> прижать элемент ко всем четырём сторонам родителя.

---

# 36. Что делает `z-index`

`z-index` управляет порядком расположения элементов по глубине.

В нашем случае:

```text
текст
кнопка
   ↑
overlay
   ↑
фоновая фотография
```

Чтобы затемнение не перекрывало содержимое, используется отдельный слой.

> [!warning]
> `z-index` работает в контексте позиционирования и stacking context. Если слои начинают вести себя неожиданно, сначала проверяйте `position`, `z-index` и структуру родительских элементов.

# 38. Почему здесь Grid

В макете текст находится слева, кнопка — справа.

Мы делим строку:

```text
┌───────────────────────────────┬──────────────┐
│          текст                │    кнопка    │
│             2fr               │     1fr      │
└───────────────────────────────┴──────────────┘
```

Это проще выразить через Grid.

# 40. Состояние `:hover`

```css
.bet-button:hover {
  transition: 0.4s;
  cursor: pointer;
  scale: 1.09;
}
```

`:hover` срабатывает, когда курсор находится над элементом.

`cursor: pointer` показывает, что элемент можно нажать.

`scale` немного увеличивает кнопку.

# 50. Почему `flex-direction: column`

По умолчанию Flex располагает элементы горизонтально.

Но здесь нам нужно:

```text

   ↓
```

Поэтому:

```css
flex-direction: column;
```

меняет основную ось на вертикальную.


распределяет свободное пространство между элементами.

В результате заголовок остаётся сверху, а описание — снизу.

Это особенно удобно для карточек одинаковой высоты.

# 68. Как определить, что использовать: Flex или Grid

Упрощённое правило:

### Flex

Используем, когда элементы образуют **одну основную линию**.

Например:

```text
иконка — иконка — иконка
```

или:

```text
пункт — пункт — пункт
```

### Grid

Используем, когда композиция имеет **колонки или строки**.

Например:

```text
меню | логотип | контакты
```

или:

```text
логотип | текст
```

В нашем проекте используются оба подхода.

# 69. Почему нельзя сразу копировать значения из CSS

Плохой способ обучения:

```css
margin-top: 180px;
padding: 133px;
width: 693px;
```

и просто запомнить эти числа.

Правильный вопрос:

> **Откуда взялось это значение?**

Например:

```css
.lots {
  margin-top: 180px;
}
```

Нужно понимать:

> В Figma между предыдущей секцией и блоком лотов измерено примерно 180 px, поэтому это расстояние переносится в CSS.

Таким образом студент учится не запоминать CSS, а **измерять макет**.

# 72. Как искать ошибку

Предположим, заголовок оказался слишком низко.

Не нужно менять сразу:

```css
font-size
line-height
margin
padding
position
```

по очереди случайным образом.

Нужно проверить:

1. положение самого блока;
2. `padding`;
3. `margin`;
4. `line-height`;
5. размеры родителя;
6. позиционирование.

Такой подход называется **отладкой**, а не подбором значений методом проб и ошибок.

# 73. Типичные ошибки начинающего

## Ошибка 1. Всё делать через `position: absolute`

Можно практически весь макет расположить абсолютными координатами, но такой код будет плохо поддерживаться.

Сначала рассматриваем:

- обычный поток;
- Flex;
- Grid;
- margin;
- padding.

И только затем используем абсолютное позиционирование там, где оно действительно нужно.

---

## Ошибка 2. Делать всё `<div>`

Так теряется семантика.

Вместо:

```html
<div class="header">
```

используем:

```html
<header class="header">
```

Вместо:

```html
<div class="menu">
```

используем:

```html
<nav>
```

если это действительно навигация.

---

## Ошибка 3. Делать отступы пробелами

Нельзя пытаться выравнивать интерфейс так:

```html
текст          текст
```

Для расположения используются CSS:

```css
margin
padding
gap
flex
grid
```

---

## Ошибка 4. Использовать `<br>` для построения всего дизайна

`br` действительно используется в контактном адресе, где перенос строки является частью отображения адреса.

Но нельзя строить всю композицию страницы с помощью множества `<br>`.

---

## Ошибка 5. Путать `margin` и `padding`

### `padding`

Расстояние **внутри** элемента.

```text
┌─────────────────┐
│    padding      │
│   ┌─────────┐   │
│   │ content │   │
│   └─────────┘   │
└─────────────────┘
```

### `margin`

Расстояние **снаружи** элемента.

```text
┌───────────────┐
│    элемент    │
└───────────────┘
      margin
```

# 77. Главное, что нужно понять

Вёрстка по макету — это не процесс:

> «Посмотрел на картинку → написал случайный CSS → пока не стало похоже».

Это процесс преобразования:

```text
ВИЗУАЛЬНЫЙ МАКЕТ
       ↓
АНАЛИЗ
       ↓
СТРУКТУРА
       ↓
HTML
       ↓
LAYOUT
       ↓
CSS
       ↓
ТИПОГРАФИКА
       ↓
ИЗОБРАЖЕНИЯ
       ↓
ИНТЕРАКТИВНОСТЬ
       ↓
ПРОВЕРКА
       ↓
ГОТОВАЯ СТРАНИЦА
```

Именно этому навыку и посвящена проектная работа.

> [!tip] Формула хорошей вёрстки
> **Сначала понять макет → затем выбрать HTML-структуру → затем выбрать способ расположения → затем написать CSS.**
>
> Не наоборот.
